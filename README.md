# 问数 Web 平台

> 面向中小学生的对话式数学陪学 Web 平台
> 平台已收敛为**单一学生端**：学生端 + 问数智能体 + 学习报告（原家长端功能已压缩进学生端）。
>
> 技术框架见 **[🏗 项目框架（目标架构）](#-项目框架目标架构)**：当前仓库是一期实现，蓝图规定了分层、选型与逐层替换路线。
> 每日改动（需求 → 改动 → 验证）记录见 **[开发文档.md](./开发文档.md)**。

|----|------|------|------|
| 学生端 | `13800000001` | `123456` | 林小明（八年级） |

| 管理端 | `admin` | `admin123` | 运营：经营看板 + 题库 + 错因字典 + 会员订单 / 会员成员 |

登录页提供「课堂演示账号」一键填入按钮（学生 / 运营各一个）；也支持自助注册（验证码在演示环境会直接回显）。

登录后按角色自动分流：学生进 `frontend/pages/student/home.html`，运营进 `frontend/pages/admin/console.html`；学生若直接访问管理端页面，会被页面守卫送回学习首页。

> **产品定位**：面向 **学生与家长**（家长与学生共用同一入口，「学习报告」页即家长视角）。
> 因此**不设教师端、不设班级课堂**——原教师角色与班级维度已下线，教学引导全部由智能体「小问」承担。

会员领航舱的付款也走演示逻辑：用 13800000001 下单会**直接支付成功**并弹出开通回执，不接真实支付网关（付款码是每次随机生成的）。

## 🏗 项目框架（目标架构）

> 这一章是**架构蓝图**：先确立问数星途要落成的完整技术框架，再按层替换实现。
> 当前 `frontend/` + `backend/` 是它的一期可运行实现（原生 HTML/CSS/JS + Express + 内存数据），**本章不涉及代码改动**，只固定分层、选型与演进路线。
> 一句话原则：**先把数据如何往返想清楚，虚线部分按产品需要接入。**

### 一、总体通用范式

几乎是所有系统的底层通用范式，问数星途同样落在这套范式里。

```text
用户端（学生 / 家长）      ──┐
                            ├── HTTPS / JSON ──▶ 服务端：Java + Spring Boot + 若依（权限 + 业务）
管理端（运营）           ──┘                        │
                                                     ├──▶ MySQL       业务数据（业务主记录）
                                                     ├──▶ Redis       缓存与短期状态
                                                     ├──▶ 图片存储     文件（头像 / 拍照 / 手绘图）
                                                     └──▶ AI 服务      模型与智能体 ──▶ 知识库

可选（虚线部分，按产品需要接入）：
智能终端硬件（智能手写板 / 摄像头传感器） ⇄ MQTT / TLS ⇄ MQTT Broker ⇄ 服务端（数据上报 / 指令下发）
```

### 二、分层框架总览

| 层 | 目标选型 | 在问数星途承载什么 | 当前实现（一期） |
|----|----------|--------------------|------------------|
| 用户端 | Vue 3 + Vite（Web） | 学生端：首页 / 讲题课堂 / 问数智能体 / 学习报告 / 答题星球 / 会员领航舱 | 原生多页 HTML + CSS + JS（`frontend/pages`） |
| 管理端 | 若依 RuoYi-Vue 内置后台 | 运营：知识点与题库管理、错因字典、会员方案与订单、数据看板 | 原生控制台 `frontend/pages/admin/console.html` + `/api/admin/*`（权限码校验） |
| 接入层 | Spring Boot + Spring MVC | HTTPS / JSON 接口、参数校验、统一异常、鉴权过滤 | Express 路由（`backend/src/routes`） |
| 业务层 | Spring Boot Service | 认证、讲题脚本、检查点判分、错因诊断、等级与积分、学习报告、会员订单 | `backend/src` 各模块 |
| 权限与基座 | 若依 RuoYi | 登录权限 / 菜单管理 / 代码生成；角色（学生 / 运营）与按钮级权限 | HMAC 令牌 + 会话缓存 + 角色 / 权限码（`backend/src/permissions.js`、`middleware/auth.js`） |
| 持久层 | MyBatis / MyBatis-Plus | 知识点、讲题步骤、答题记录、学习会话、错因、会员订单的 SQL 映射 | 仓储层 `repositories/` + 轻量表引擎 `db/table.js`（与 `models/mockData.js` 同一份数据） |
| 数据库 | MySQL（主）/ PostgreSQL（扩展）/ 达梦 DM、金仓 KingbaseES（国产适配） | 业务数据主存储：表、主键、SQL、索引 | 18 张表定义 + 生成 DDL（`db/schema.js` → `schema.sql`），默认内存驱动（`DB_DRIVER=mysql` 预留） |
| 缓存 | Redis | 热点列表少查库、登录状态判会话有效、频率计数防刷 | 缓存层 `cache/`：会话 / 注销标记 / 验证码 / 频率计数，Redis 语义（`CACHE_DRIVER=redis` + `REDIS_URL`，连不上自动降级） |
| 文件存储 | 对象存储 / 图片服务（MinIO 等） | 头像、错题拍照、手绘图形、讲题配图 | 头像支持 emoji / 文字 / 图片链接 / data URL |
| AI 服务 | 大模型 + 智能体（RAG 知识库） | 问数智能体：三角色对话、引导式教学五步、不泄答案护栏、工具调用 | 配置中心统一管理（`config/index.js`）+ 自研规则引擎（离线兜底）+ OpenAI 兼容 function calling（默认接 DeepSeek） |
| 智能终端（可选） | MQTT Broker + 智能手写板 / 摄像头传感器 | 手写作答数据上报、拍照讲题、姿势与专注度提示 | 未接入（虚线部分） |

### 三、前端框架认知

**Node.js 负责运行开发工具，浏览器负责运行页面。**

```text
uni-app（小程序 / App / Web）      Electron（桌面应用外壳）
        │                                  │（可搭配 Vue 或 React）
        ▼                                  ▼
      Vue 3  ◀── 组织页面与组件 ──▶  React
                        │
          ┌─────────────┼─────────────┐
        HTML 结构     CSS 样式     JavaScript 交互
```

| 技术 | 适用场景 | 在问数星途的定位 |
|------|----------|------------------|
| HTML / CSS / JS | 一切 Web 页面的基石 | **当前已落地**；Vue 页面最终也编译成这三样 |
| Vue 3 | 单页应用、组件化的用户端与后台 | **目标前端主力**，学生端与会员页组件化重构 |
| React | 生态大、招聘面广 | 备选方案，同一项目不混用 |
| uni-app | 一套代码出小程序 / App / Web | 后续移动端（家长微信小程序端、学生端 App） |
| Electron | 桌面应用外壳 | 后续桌面端（家庭大屏学习舱） |

### 四、后端框架认知

**Java 写逻辑，Spring Boot 帮助启动，若依提供项目基座。** 现成基座 + 自己的业务规则。

| 技术 | 职责 | 在问数星途中的落位 |
|------|------|--------------------|
| Java | 编写业务逻辑 | 讲题推进、判分、错因、积分、订单等业务代码 |
| Spring Framework | 组织对象与提供 Web 能力 | IoC 容器托管 Service / Controller，MVC 暴露 HTTP 接口 |
| Spring Boot | 简化配置与启动 | 单体启动、配置外置、内嵌容器 |
| 若依 RuoYi | 登录权限 / 菜单管理 / 代码生成 | 管理端基座 + 角色权限骨架，省去重复的权限与后台代码 |
| MyBatis | SQL 映射 | 知识点、答题记录、会员订单等表的读写 |
| MySQL | 关系型数据库 | 业务数据主库 |

### 五、数据库：先懂共性，再认识产品

**本课用 MySQL；表、主键与 SQL 的基本思想可以迁移**，换产品仍需检查驱动与 SQL 兼容。

| 概念 | 说明 | 问数星途中的例子 |
|------|------|------------------|
| 主键 | 唯一标识一行记录 | `user_id`、`order_no`、`lesson_id` |
| SQL | 结构化查询语言，增删改查 | 查某学生的错题本、按周统计学习时长 |
| 索引 | 加速查询的目录 | 按 `phone` 查登录用户、按 `end_at` 查有效会员 |

| 数据库 | 定位 | 在问数星途的角色 |
|--------|------|------------------|
| MySQL | 本课实操 | 业务数据主存储（一期目标） |
| PostgreSQL | 扩展生态 | 需要 JSON / 复杂分析时的备选 |
| 达梦 DM | 国产适配 | 政企 / 校园私有化部署的合规选型 |
| 金仓 KingbaseES | 国产适配 | 同上，换库后必须回归驱动与 SQL 兼容性 |

### 六、Redis：缓存常用数据与短期状态

**让重复读取更快，也为登录状态和请求计数提供支持。** 由后端读写和管理过期。

| 用途 | 说明 | 在问数星途中的落位 |
|------|------|--------------------|
| 热点列表 | 高频读取的数据放缓存，少查数据库 | 知识点树、星系天梯榜、会员方案与价格 |
| 登录状态 | 保存会话，判断登录是否有效 | 令牌 + 会话状态，支持多端登录与踢下线 |
| 频率计数 | 计数器，防止频繁请求 | 短信验证码、智能体问答、一键生成学习报告的限流 |

> 边界：**业务主记录仍落 MySQL，热数据与短期状态放 Redis**——MySQL 像保险柜存主记录，Redis 像内存便签存常用数据。

### 七、演进路线（不动现有代码，逐层替换）

| 步骤 | 动作 | 关键约束 |
|------|------|----------|
| 1 | 数据落库：把 `backend/src/models/mockData.js` 的内存数据换成 MySQL 表 + MyBatis 映射 | 先设计表结构、主键与索引 |
| 2 | 接入 Redis：登录态、验证码与智能体限流、知识点树缓存 | 主记录仍在 MySQL |
| 3 | 后端换基座：业务逻辑平移到 Java + Spring Boot + 若依 | 接口路径与返回结构保持不变，前端零改动 |
| 4 | 前端组件化：原生多页 → Vue 3 + Vite | 直接复用 `qw-*` / `sq-*` 类名与 `space.css` 主题 |
| 5 | 管理端：基于若依内置后台做运营端 | 题库、错因字典、会员订单、数据看板 |
| 6 | 多端：uni-app（家长小程序 / 学生 App）、Electron（家庭大屏学习舱） | 复用同一套接口契约 |
| 7 | 可选：MQTT Broker 接入智能手写板 / 摄像头传感器 | 数据上报与指令下发，按产品需要接入 |

### 八、迁移不变量（保证平滑替换）

- **接口契约**：统一 `/api/<模块>/<资源>` 路径、成功用 `{ data }` 包裹、失败用 `{ error }` + HTTP 状态码
- **鉴权方式**：`Authorization: Bearer <token>`，前端 `auth.js` 不感知后端实现
- **样式体系**：`qw-*`（公共组件）/ `sq-*`（星途主题）类名与 `space.css` 主题章节不变
- **数据口径**：星尘（学习所得）/ 星钻（等值充值）、免费版开放星球数（1 颗）、五维能力雷达、会员有效期与续费顺延规则不变
- **安全底线**：答案只存在于服务端，所有对外接口继续经 `safeLesson()` 剥离

## 🤖 问数智能体

### 三种角色

| 角色 | 图标 | 定位 | 专属工具 |
|------|------|------|----------|
| 讲题老师 | 🎓 | 陪学生走完当前讲题步骤，分级提示、对话判题、变式练习 | `get_hint` `check_answer` `generate_variant` … |
| 错题侦探 | 🕵️ | 复盘「为什么错」，把错误归到 7 类错因并给检查动作 | `get_error_book` `classify_error` |
| 学习规划师 | 🧭 | 按进度缺口排出三天学习计划、生成学习报告、情绪疏导 | `generate_report` `make_plan` |

### 核心能力

- **前置限制词（12 类 · 148 条规则）**：消息进入大模型之前先过 `blocklist.js`，命中即拦截并改用安全话术 —— 自伤 / 轻生、色情低俗、暴力违法、**诈骗诱导充值**、**线下见面**、辱骂攻击、作弊代写、隐私安全、私下联系、提示词注入、索要答案、无关闲聊。既守住未成年人安全边界，也不把违规内容送给模型。
- **不泄答案兜底**：10 条「要答案」正则 + 出站二次检查，模型若直接报出正确选项会被改写为引导话术；工具接口全部剥离 `correct` 字段，答案只留在服务端。
- **一键自动生成**：智能体页有「📊 一键生成学习报告 / 🗓 近一周报告 / 📕 错题记录 / 🛡 安全边界」四个按钮，直接读服务端算好的真实数据，不依赖大模型也能出结果。
- **引导式教学骨架（通用模版）**：内置「情境唤醒 → 概念建构 → 抽象归纳 → 标准训练 → 错因诊断」五步闭环、答题六步 SOP 与 6 类错因矩阵（概念不清 / 策略逻辑错 / 符号公式错 / 纯计算错 / 空白看不清 / 情绪跑题）。骨架随每一步注入系统提示词，大模型只在骨架里判答、给一句话短评和降级追问，不自由发挥；同一道题提示上限 3 次，超过就展示标准步骤图并标注「本题需要老师介入」。
- **语音对话**：智能体底部是「🎤 按住说话 / ⌨ 键盘输入 / 🔊 语音播报 / ⚙ 语音设置 / 🔔 喊"小问"唤醒」一排按钮（小屏自动换行），基于浏览器原生 Web Speech API。说话时气泡上会实时显示识别结果，没听清或没权限会自动降级提示；浏览器不支持语音时自动隐藏麦克风，只保留键盘输入。对话气泡都带 `20:31 · 小问轻声提问` 这样的时间戳与说话人标签。
- **语音声音可选**：点「⚙ 语音设置」弹出浮层，里面有「🗣 声音」下拉与「⏩ 语速」滑杆，声音列表读浏览器真实嗓音并**中文优先、本地优先**排序（微软 Huihui / Kangkang / Yaoyao 一类），换声或调语速会立刻用「你好呀，我是小问」试听一句；默认自动挑一个中文嗓音，避免用英文嗓子念中文。选择存在 `localStorage.qw_voice` / `qw_voice_rate`，下次打开仍然生效。浮层默认收起（点外面或按 Esc 关闭），所以不会挤占对话区高度。
- **小问吉祥物（奶酪猫）**：每个学生端页面右下角常驻一只奶酪小猫，**点一下才展开**「小问快问」小聊天框（复用同一个对话组件，紧凑模式），随时插队问一句；默认是收起的，不会挡住页面；招呼气泡 8 秒后或页面滚动时自动让位，Esc / ✕ 可收起。
- **流式输出**：`POST /api/agent/chat/stream` 以 NDJSON 返回 `start → tool → delta → done`，前端边收边打字。
- **工具轨迹可视化**：对话中会显示「翻错题本 / 生成学习报告 / 出变式题」等调用轨迹，让学生知道智能体做了什么。
- **主动建议**：`GET /api/agent/suggest` 结合真实学习记录生成「现在最值得做的事」，打开页面就会给出，并可一键切换角色。
- **学习报告 / 计划卡片**：报告与计划会渲染成结构化卡片，而不是一长段文字。
- **回复反馈**：每条回答可点「👍 有帮助 / 🤔 还没懂」，反馈写入学生画像并触发更细的讲解。
- **会话记忆 + 学生画像**：按 `学生 × 知识点` 保存最近 24 条消息；画像记录提示次数、对错、错因、被拦次数、反馈，用于调整提示级别。
- **离线可用**：未配置大模型 Key 时自动使用内置规则引擎（15+ 意图识别），全部功能仍可演示。
- **接入大模型**：`backend/.env` 里配置 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` 即可切换为 OpenAI 兼容的 function calling，调用失败会自动降级到规则引擎。当前默认接 **DeepSeek**（`https://api.deepseek.com/v1`），可用模型 `deepseek-flash`（快、省）/ `deepseek-v4-pro`（更强）；顶栏与智能体页会显示当前实际使用的模型名。

### 引导式教学骨架（通用模版）

原则是「脚本管骨架，大模型管临场」：骨架写在 `backend/src/agent/scaffold.js`，每一步都会随系统提示词一起注入模型，模型只能照着骨架判答、给一句话短评、做降级追问，不自由发挥。

**五步教学闭环**

| 阶段 | 目标 | 图模板 | 答不出时的降级 |
|------|------|--------|----------------|
| 1 情境唤醒与认知冲突 | 从旧知引出新知，制造「原来的办法不够用了」 | 前置知识图 / 生活场景图 | A. 变了 / B. 没变 / C. 还不知道 |
| 2 概念建构与直观感知 | 让图自己说话，学生自己发现规律 | 面积拼图 / 函数图像 / 辅助线 | A. 变大 / B. 变小 / C. 没关系 |
| 3 抽象归纳与符号化 | 从具体数字走到一般公式或定理 | 公式推导高亮图 | 退回阶段二，用更简单的数字重走 |
| 4 标准题训练与独立作答 | 用刚学的知识做一道题，暴露真实问题 | 原题固定图 + 答题区 | A. 先找条件 / B. 先套公式 / C. 不知道从哪开始 |
| 5 错因诊断与提问式纠正 | 定位错因，用提问让学生自己改对 | 原题高亮错误步骤 | 变式确认，直到真的掌握 |

**引导式答题六步 SOP**：读题与信息提取 → 策略选择脚手架 → 独立作答过程识别 → 错因分档与一句话短评 → 提问式纠正 → 变式训练与掌握反馈。

**通用错因分类矩阵**（模型只在库里选标签，不自由发挥）

| 错因大类 | 典型表现 | 系统应对 |
|----------|----------|----------|
| 概念不清 | 忽略 a ≠ 0；把勾股定理用在非直角三角形 | 退回「概念建构」，用图重新提问适用条件 |
| 策略 / 逻辑错 | 该因式分解却硬套公式；条件与结论倒推 | 退回策略选择，给方法选择树 |
| 符号 / 公式错 | 求根公式分母写成 a；移项忘记变号 | 高亮公式模板，代入参数重算这一步 |
| 纯计算错 | 3 × 4 = 7；开平方漏掉负数根 | 不重讲知识点，只重算这一步 |
| 空白 / 看不清 | 未作答；拍照太模糊 | 绝不报错，降级为选项或追问 |
| 情绪 / 跑题 | 「烦死了」「直接告诉我」 | 触发拦截，换轻松语气 + 最简选项 |

**红线**：一句话短评的模板是「你在「某一步」好像出现了一点小状况（错因类型），我们回到黑板上的图再检查一下？」——只指出错因类别，绝不铺开完整正解；同一道题提示上限 3 次，超过即展示标准步骤图并标注「本题需要老师介入」。

| 智能体 | 自研规则引擎（离线兜底）/ OpenAI 兼容 function calling（在线，默认接 DeepSeek），由 `AGENT_PROVIDER` 切换 |
| 图案 | 自研 SVG 生成器 `frontend/src/scripts/space-art.js`（零依赖、无网络请求、无图床） |
| 传输 | 自写 gzip 中间件 `backend/src/middleware/compress.js`（Node 内置 zlib，零新增依赖）+ 带 ETag 的静态资源压缩缓存 |

## 📝 开发说明

1. **不泄答案原则**：答案只存在于 `backend/src/models/lessons.js`，所有对外接口都经过 `safeLesson()` 剥离，智能体的工具接口同样不返回答案。
2. **样式与图标都不依赖网络**：页面关键样式写在 `common.css` 的 `qw-` 类和真实的 `:root` 主题变量里，图标用本地 `assets/vendor/lucide.min.js`——断网（内网部署 / 离线演示）时布局、配色、图标全部正常。星途主题补充在 `space.css`（必须排在 `common.css` 之后才能正确覆盖）。想让别人也能访问，见 [`部署文档.md`](./部署文档.md)。
3. **演示数据不落库**：进度、积分、画像都保存在服务端内存，重启即恢复初始状态。
